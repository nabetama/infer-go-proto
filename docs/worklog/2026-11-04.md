# 2026-11-04

## ブランチ全体のレビューの指摘の修正

- 関数の中で宣言した型に、関数名を付けた名前を使うようにした（`<パッケージ>::row$F`、メソッドの中なら `row$S$M`、同じ関数に同名の型が複数あれば `$1`、`$2`）。以前は別々の関数の `type row struct{ ID int }` と `type row struct{ Name string }` が同じ名前になり、型の宣言が 1 つしか出力されず、`infer capture` が `field ...row.Name is not declared` で失敗していた。`testdata/src/localtypes` を Infer に取り込めることをテストで確かめた。
- ジェネリクスの型のポインタの型引数に `ptr_` を付けるようにした。`Request[*T]` と `Request[T]` が同じ名前になっていた。
- `typeConv` が struct の型の宣言ごとに元の Go の型を覚え、`types.Identical` でない型が同じ名前になったら `Translate` がエラーを返すようにした。go2sil は終了コード 1 で終わる。パッケージ `a.b` と `a_b` の同名の型、名前が同じになる無名の struct（`struct{X_ *int}` と `struct{X []int}`）で確かめた。
- パターンに一致するパッケージがないとき（`./docs/...`）、空の `.sil` を出力して終了コード 0 で終わっていた。`translate.Load` がエラーを返すようにした。
- `bun.Safe` への変換だけが危険な関数になるサンプル `SearchUsersSafeArgBad`（`Where("name = ?", bun.Safe(req.OrderBy))`）を `examples/grpcsvc` に足した。`SearchUsersSafeBad` は `OrderExpr` でも報告されるので、`.inferconfig` の `schema::Safe` の行が壊れても e2e テストが失敗しなかった。`.inferconfig` から `schema::Safe` の行を消すと、e2e テストが `SearchUsersSafeArgBad` が足りないことで失敗することを確かめた（`.inferconfig` は元に戻した）。
- README の「本体のない宣言の呼び出しは、引数の taint が戻り値に伝わる」を直した。小さなサンプルを go2sil と Infer にかけ、`strings.ToUpper(Source())` と `fmt.Sprintf("%s", Source())` は報告され、`strings.Join`、`fmt.Sprint`、`fmt.Fprintf` で書いた `bytes.Buffer` の `String()`、`strings.Builder` の `WriteString` の後の `String()` は報告されないことを確かめた。
- インタフェースを通したメソッド呼び出しは実装を解析しないこと（`func ViaIface(f Finder) { f.Find(Source()) }` は、唯一の実装が危険な関数に渡していても報告されなかった）を README の既知の制限と設計ドキュメントに書いた。
- README の警告の形式に、オペランドが原因のときに付く ` (operand <型>)` を書いた。
