# 2026-10-28

## 決めたこと

- Go を Infer で解析できるようにする。方法は、Go で書いた変換ツールで `go/ssa` から Textual（`.sil`）を出力し、`infer --capture-textual` に渡すもの。LLVM ビットコードを経由する方法（gollvm / TinyGo → Infer の llvm フロントエンド）は、Infer の llvm フロントエンドが Swift 向けに調整されているため採らない。
- 最初に検出するものは「外部入力が危険な処理に届くもの」（taint）。リソースの閉じ忘れや nil による panic は後回し。
- 想定する構成は、connect / gRPC のハンドラを入力元、bun / `database/sql` の SQL 文字列引数を危険な関数とするもの。
- リポジトリは公開予定。サンプルは汎用的な例だけで書く。

## 調べたこと

- facebook/infer の最新リリースは v1.3.0（2026-05-12）。バイナリは `infer-osx-arm64-v1.3.0.tar.xz` と `infer-linux-x86_64-v1.3.0.tar.xz`。
- 手元の環境は Go 1.27.3（darwin/arm64）。Infer は未インストール。
- `infer/src/` のフロントエンドは clang、java、erlang、python、rust、llvm（Swift）など。go はない。
- 外部の言語を足す方法として、issue facebook/infer#2045 でメンテナが `.sil` を出力して `--capture-textual` で取り込む方法を案内している。
- Pulse の taint 設定の仕様は `infer/src/atd/pulse_config.atd`。`taint_target` に `ArgumentPositions` などがある。
- `PulseTaintOperations.ml` の `taint_initial` が、入力元に指定した関数の引数に taint を付ける。
- Textual の `.source_language` に Go はない（`Textual.ml` の `Lang`）。

## 実装計画

- `docs/plans/2026-10-28-go-taint-poc.md` を作成した。
- 作業用ブランチ `go-taint-poc` を作成した。
- 計画のために調べたこと:

- Infer の挙動のうち未確認のものは、計画の Task 1 で、手書きの `.sil` を使うテストで確かめる。未確認なのは、引数の型を指定した入力元、本体のない関数を通る taint の伝わり方、レシーバがあるときの引数の番号。

## Task 1: Infer の用意と挙動の確認

- `scripts/install-infer.sh` で Infer v1.3.0 の公式バイナリを `.tools/infer` に展開した（`.gitignore` に `.tools/` と `infer-out/` を入れた）。
- `internal/infertest` に、Infer を呼ぶ補助関数（`Bin`、`Run`）と、手書きの `.sil` で Infer の挙動を確かめるテストを置いた。結果は設計ドキュメントの「v1.3.0 のバイナリで確かめたこと」に書いた。要点は次のとおり。
  - `.source_language` は `c` にした。
  - `ArgumentsMatchingTypes` による引数の型での入力元、taint の付いたポインタのフィールド、本体のない宣言の引数から戻り値への伝わり方、レシーバを 0 番とする `ArgumentPositions` は、計画の想定どおりに動いた。
  - 本体のない宣言に渡した `*Slice` のフィールドの taint は戻り値に伝わらない。`fmt.Sprintf` には本体つきのモデルが要る。
  - `define Cls.m` のクラスの部分は Infer の中で落ちる。クラスだけが違う同じ名前のメソッドがあると取り込みが失敗する。計画の `mangle.Func` の「class と name に分ける」形は使えないので、トップレベルの名前（例: `example_com::orm::Q$Where`）で出力する必要がある。
  - `sprintf` のような C の標準ライブラリと同じ名前の関数は、定義した本体が使われない。
