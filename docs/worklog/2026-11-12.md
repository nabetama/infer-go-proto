# 2026-11-12

## マージ前に残っていた 2 つの問題の修正

- 別のパッケージにある同じ書き方の無名の struct（`struct{ x int }` のように小文字のフィールドを持つもの）で、go2sil が `go2sil: types struct{x int} and struct{x int} both map to the Textual type "go::struct$struct_x_int_$"` を出して終了コード 1 で終わっていた。小文字のフィールドはパッケージに属するので、パッケージが違うと `types.Identical` は false になるが、無名の struct の名前にはパッケージを含めないので同じ名前になる。衝突かどうかを `types.Identical` ではなく、出力する Textual の型の宣言（フィールドの名前と Textual のフィールドの型を順に）が同じかで決めるようにした。同じなら 1 つの宣言を共有し、違えば従来どおりエラーにする。`testdata/src/anonpkg/an1` と `an2` で、エラーにならず `infer capture` が通ることと、`go2sil ./an1 ./an2` が終了コード 0 で終わることを確かめた。`a.b` と `a_b` の同名の型、`struct{X_ *int}` と `struct{X []int}` のテストは変えずに通る。
- 対象のパッケージの中のジェネリクスの関数の呼び出しで、インスタンスの定義も宣言も出力されていなかった（`F$int$` を呼ぶが定義がなく、`infer capture` が `is not declared` で失敗）。インスタンスも元の関数の型パラメータを `TypeParams()` で返すので、`enqueue` がインスタンスも飛ばしていた。型パラメータがあり型引数がない関数だけを飛ばすようにした。`testdata/src/generic` で、`F$int$`、`F$string$`、`Box$string$$Get`、`Wrap$int$`、`Wrap$string$` が本体つきで出力され、依存パッケージの `cmp::Compare$int$` は本体のない宣言になり、警告がなく `infer capture` が通ることを確かめた。Pulse で `ViaGeneric`（`Source` から `F` を通って `Sink`）と `ViaBox`（`Box[string].Get` を通る）が報告され、`ViaGenericClean` は報告されないことを確かめた。
- ジェネリクスの関数の中で宣言した型は、`go/ssa` がインスタンスごとにどのスコープにも属さない別の型を作るので、`Wrap[int]` と `Wrap[string]` の中の `type cell struct{ v T }` が同じ名前 `<パッケージ>::cell` になり、フィールドの型が違うので衝突のエラーになった。インスタンスの型引数を付けた名前（`<パッケージ>::cell$Wrap$int$`）を付けるようにした。
- e2e テストの want と got は変わらない（`.inferconfig` と e2e のテストは変えていない）。
